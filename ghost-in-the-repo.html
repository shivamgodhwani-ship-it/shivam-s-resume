Ghost in the Repo

Git-History Bug-Risk Predictor  ·  Solo Build  ·  2026

Doesn't review your diff — studies your repo's bugfix history to predict what breaks next
View on GitHub →

The Problem

Most AI code review tools score a diff in isolation — they look at the change in front of them and judge it on its own. That misses something a diff alone can't show: which files in a codebase have an actual track record of breaking, regardless of what the current change looks like.

Ghost in the Repo flips the question. Instead of reviewing what you just wrote, it studies what your repository's own history says about where things tend to go wrong.

How It Works

For every source file in a repository, the tool computes a risk score from four signals:

01
Bugfix Ratio

The percentage of a file's commits whose message mentions fix, bug, crash, or regression.

02
Churn

How often the file changes, log-scaled so a handful of very active files don't dominate the score unfairly.

03
Recency

An exponential decay that favours files touched more recently — old churn matters less than current churn.

04
Odd-Hour Commits

The share of a file's commits made late at night — a rough proxy for rushed work, used as a tiebreaker signal.

Scores are confidence-weighted so a file with a single lucky or unlucky commit can't outrank one with real sustained bugfix history — a small-sample-size trap I hit and fixed during testing. The top-ranked files are then passed to an LLM, which turns the raw numbers into a one-sentence, plain-English explanation of why a given file is risky.

Validation

Tested against Flask's full commit history (~5,500 commits). The scores matched intuition — CLI and context-handling code ranked highest, which lines up with Flask's actual, documented history of tricky edge cases in exactly those areas.

Design Decisions

Swappable LLM Backend

Explanations run on the Anthropic API by default, or a local Ollama model with an identical input/output shape — a one-line swap, no other code changes needed

Score-Only Mode

Can run without any LLM calls for an instant, free risk ranking

Honest About Limits

Bugfix detection is keyword-based on commit messages, not linked issue trackers — a reasonable proxy, not ground truth

Stack

Built with Python · Anthropic API (or local Ollama) · Git log parsing

Key Takeaway

A repository already contains the data needed to flag its own weak points — most tools just don't look backward far enough to find it. The harder part wasn't the scoring math; it was being honest about where a keyword-based proxy stops being reliable, and saying so directly in the documentation rather than overselling the signal.
